# seekdeep-util 输出保留

[English](README.md) | 中文

`seekdeep_util::output_retention` 是一个轻依赖的有界保留库。它只回答机制问题：
“保留了什么，又省略了什么？”退出状态、文件分组、行号、提供方失败、spill 文件和
面向模型的恢复文案仍由具体工具负责。

这是库，而不是服务或插件。它不注册内容、不发送事件，并且状态只属于一次 retainer
累积。

## API

`ItemRetainer<T>` 保留有序逻辑项的前若干项，同时继续统计每一个已观察项。`push`
返回 `PushDecision`，`finish` 返回保留项、精确的已观察和已保留数量，以及一个
`Omitted` 值。

`TextRetainer` 通过三种 `TextRetentionStrategy` 之一限制字节流：

- `Head` 保留稳定前缀。
- `Tail` 保留最后一个字节窗口。
- `HeadTail` 保留稳定前缀和后缀，并省略中间部分。

`try_*` 构造函数保留源 API 的 JavaScript 数值边界，并以字段专用诊断拒绝负数、
小数和非有限预算。Rust 原生构造函数接受已经验证的 `usize` 预算。

`describe_omitted` 渲染标准省略子句；`format_retention_notice` 将该子句与消费方
提供的恢复指引组合。

## 资源语义

项 retainer 和文本 retainer 相互独立，因为两者的资源模型不同。项消费方可以保留
完整旁路数据，同时只保留内联预览，因此能够知道精确的省略项数。文本是字节流：
head、tail 和 head-tail 保留提供有界内存，并报告精确的省略字节数。

`truncated` 严格表示预算事实：retainer 因预算省略了本来可用的输入；它绝不表示
上游操作不完整。权限失败、跳过二进制文件、提供方部分失败和不可读候选项仍保留在
所属工具的领域结果中。

## UTF-8 边界

文本上限和省略数量按字节而不是字符计算。在 `finish` 时，跨越 UTF-8 码点的切口会
被修剪，因此保留边界本身不会引入替换字符。前缀和后缀分别解码，所以绝不会跨越
被省略的中间部分重建码点。已经完整位于保留区域内的非法字节仍使用有损解码，与源
行为一致。

## 消费方映射

- `glob`、`grep` 和 web-search 来源预览使用项 head 保留。
- 进程和 shell 输出使用文本 tail 或 head-tail 保留。
- 有界响应正文使用文本 head 或 head-tail 保留。

消费方仍负责 spill 持久化、分页、面向模型的通知和缓存影响。文件读取所用的行窗口
约定仍是独立抽象，因为单个省略数量无法描述分页窗口的两侧。

## 模型与缓存影响

没有直接影响。消费方决定如何让保留内容和省略元数据对模型可见，并负责所有请求
前缀变化。

## 限制

项保留只支持 head。文本保留面向字节；行窗口和字符窗口需要领域专用渲染器，切口
可能丢弃部分 UTF-8 边界字节，以保持返回文本有效。
