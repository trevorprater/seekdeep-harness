# Agent Note: 在 CI 中验证原生运行时边界

Status: implemented

[English](2026-09-25-native-ci-boundaries.md) | 中文

## 问题

Cargo 测试二进制可以编译成功，但调用方仍可能选择已经不存在的测试目标，或在重新执行自身的辅助进程中选择了零个测试。覆盖率插桩后的二进制还会位于不同于普通二进制的目录，因此相对资源查找可能只在覆盖率测试中失败。Windows 又增加了一层区别：可移植测试的路径写法可能错误，而实现本身正确；表面相似的原生 API 也可能具有不同于 Node 的路径、时间戳或错误语义。

## 决策

门禁调用方指定编译后的测试目标，并把模块过滤条件放在 Cargo 的 `--` 分隔符之后。重新执行自身的测试在精确测试名中包含模块名，并断言子进程确实执行了辅助测试。覆盖率入口在插桩前通过 `cargo xtask host-assets` 准备 Host 运行时资源，传递 Node 资源的绝对位置，并把已准备的原生可执行文件目录放在 `PATH` 首位供 ripgrep 使用。`SEEKDEEP_GATE_STREAM_OUTPUT=1` 还会即时打印子进程输出，使运行器在缓冲门禁报告结束前失联时仍留下证据。

托管门禁清单在向 `main` 推送以及手动分派 `checks` 时运行。检查失败后也会保存 Rust 依赖缓存，使后续运行能够复用构建产物。静态归档门禁使用拉取请求的基准 SHA、推送前的 SHA，或手动运行时检出的 SHA。完整 Git 历史确保基准可用，无需改变[冻结归档约定](../process/2026-07-26-frozen-agent-note-archive.md)。

PR 策略检查器在获取关联议题前，先应用现有的机器人、应用、草稿和评审状态豁免规则。依赖项发布说明中引用的上游议题编号，不得让已豁免的 PR 依赖不相关的本地议题。需要强制检查的 PR 和生命周期转换仍会解析关联议题。

使用凭据的 DeepSeek 工作流还通过构建后的 Rust Host 和 WebAssembly UI 执行固定版本源代码的真实浏览器冒烟测试。Chromium 和编译后的测试 Host 是前置条件；外部 API 密钥仅用于验证步骤，端点固定为 `https://api.deepseek.com`。临时工作区包含固定的事件溯源提示和 echo 命令测试数据。工作流保留驱动器脱敏后的日志和逐项结果，并在传输重试用例失败时保留提供方请求次数及观察到的会话历史。

[受支持平台的测试数据规则](2026-07-22-cross-platform-test-fixtures.md) 同样适用于原生测试：本地路径使用宿主路径操作，基于 Node 的测试通过 Node 调用 JavaScript 入口，只有源代码声明为 POSIX 专属的原语才在对应单个用例中排除 Windows。生产兼容性单独验证。会话根目录保留 Node 对 Windows 驱动器根路径的接受行为；文件 URL 保留平台特有的解码和错误；文件版本包含设备、inode、大小、修改时间和变更时间；Windows 重命名路径在添加逐字命名空间前完成规范化，且不丢失 UTF-16 数据。

连接取消由实际 HTTP 传输拥有。流包装器在 EOF、I/O 失败或释放时取消连接信号，协议升级则把同一所有者转交给升级后的传输。提前观察对端断连的监视器是一条额外观察路径，而非取消操作的唯一所有者。

配置监视器忽略访问通知：读取文件不得通过 Linux inotify 再触发一次读取。设置和凭据监视器也不允许访问事件重新启动等待中的防抖窗口。精确路径配置监视器在入队前过滤访问事件；取消优先于排队的观察结果，先停止原生监视器，再排空已接纳的刷新。

## 快照边界

需要改变工作目录的进程内 profile 测试在独立的测试进程中执行。信号测试会在保持主请求等待的同时并发服务标题请求，并要求 SIGINT/SIGTERM 清理在 4.5 秒内结束。该期限早于 5 秒强制退出时间。

PowerShell 工具模式快照由固定版本的 TypeScript 源实现回放生成到临时测试数据目录。其规范排序和当前描述，在重命名产品环境变量前缀后，构成 Rust 输出的预期。若源快照对源实现自身也失败，这应成为调查证据，而非修改原本匹配的生产行为的依据。

手工编写的快照脚本中，`waitForTurnEnd` 接受可选的 `minimumTurn`。带编号的等待要求最新持久化轮次已经结束，且轮次号不小于指定值；在开始轮询前就已结束的轮次同样满足条件。`waitForTurnStart` 保留等待开放轮次的语义，供取消场景使用。持久化目录和策略继承场景先阻止子代理执行，直到父代理第一轮结束，再等待结算通知轮次完成。因此，手工编写的记录在快慢运行器上都保持相同的 `next-turn` 交付方式。

## 曾考虑的替代方案

**排除失败的 Windows 测试套件。** 这会连同测试数据错误一起隐藏受支持的约定。原生路径测试数据和源实现比较能够区分这些故障，无需缩减平台测试清单。

**修改生产排序以匹配旧快照。** 固定版本的源运行时按字典顺序排列这些工具。由源实现生成预期可保留这一行为，并使 Rust 比较继续有意义。

**延长等待瞬态开放轮次的时间。** 已经结束的轮次不会重新开放。带编号的持久化结束边界能验证完成状态，无需依赖轮询速度。

**根据测试可执行文件位置查找覆盖率资源。** 插桩会改变可执行文件目录。使用所属构建提供的显式路径，既保留包迁移测试，也为覆盖率测试提供所需运行时。

## 后果

测试分别验证测试数据的可移植性、运行时行为、已安装资源和平台执行。交叉编译可以检查 Windows API 和类型，但原生文件系统行为仍需由 Windows 运行器证明。聚焦的源实现比较和快照运行，与完整工作区、覆盖率、真实提供方及发布一致性门禁构成独立证据；任何一项都不能替代缺失的结论。
