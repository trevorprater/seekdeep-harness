# Agent Note: Verify native runtime boundaries in CI

Status: implemented

English | [中文](2026-09-25-native-ci-boundaries.zh.md)

## Problem

A Cargo test binary can compile while a caller selects an obsolete target or a self-executed helper selects zero tests. Instrumented binaries also run from a different directory than ordinary binaries, so relative asset discovery can fail only in coverage. Windows adds another distinction: a portable fixture can have the wrong spelling even when the implementation is correct, while a superficially similar native API can have different path, timestamp, or error semantics from Node.

## Decision

Gate callers name the compiled test target and pass module filters after Cargo's `--` separator. Self-executed tests include their module in the exact test name and assert that the child executed its helper. Coverage stages Host runtime assets through `cargo xtask host-assets` before instrumentation, passes the Node assets' absolute locations, and prepends the staged native executable directory to `PATH` for ripgrep. `SEEKDEEP_GATE_STREAM_OUTPUT=1` additionally prints child output as it arrives, preserving evidence if a runner disappears before the buffered gate report settles.

The hosted inventory runs on `main` pushes and manual `checks` dispatches. Rust dependency caches are saved after failed checks so subsequent runs can reuse their builds. The static archive gate uses the pull-request base SHA, the previous push SHA, or the checked-out SHA for a manual run. Complete Git history makes that baseline available without changing the [frozen archive contract](../process/2026-07-26-frozen-agent-note-archive.md).

The PR policy checker applies its existing bot, app, draft, and review-state exemptions before fetching referenced issues. Quoted upstream issue numbers in dependency release notes must not make an exempt PR depend on unrelated local issues. Enforced PRs and lifecycle transitions still resolve their references.

The credentialed DeepSeek workflow also executes the pinned real-browser smoke through the built Rust Host and WebAssembly UI. Chromium and the compiled fixture Host are prerequisites; the external API key is scoped to the verification steps, and the endpoint remains `https://api.deepseek.com`. Temporary workspaces contain the fixed event-sourcing prompt and echo-command fixture. The workflow retains the driver's redacted logs and per-case result, plus the provider-attempt count and observed session history when the transport-retry case fails.

The [supported-platform fixture rule](2026-07-22-cross-platform-test-fixtures.md) also applies to native tests: local paths use host path operations, Node-based fixtures invoke their JavaScript entry through Node, and only source-declared POSIX primitives have case-level Windows exclusions. Production compatibility is verified separately. Session roots retain Node's drive-rooted Windows acceptance; file URLs retain platform-specific decoding and errors; file versions use device, inode, size, modification time, and change time; Windows rename paths are normalized before a verbatim namespace is added without losing UTF-16 data.

Connection cancellation belongs to the actual HTTP transport. The stream wrapper aborts the connection signal on EOF, I/O failure, or drop, and an upgrade transfers that same owner into the upgraded transport. The early peer-disconnect watcher is an additional observation path, not the sole owner of cancellation.

Config watchers ignore access notifications: reading a file must not trigger another read through Linux inotify. Settings and credential watchers also keep access events from restarting a pending debounce window. The exact-path config watcher filters access before queueing; cancellation takes priority over queued observations, stops the native watcher, and then drains admitted refreshes.

## Snapshot boundaries

An in-process profile fixture that changes the working directory executes in its own test process. The signal fixture serves title requests concurrently with its held main request, and SIGINT/SIGTERM settlement must finish within 4.5 seconds. That deadline precedes the five-second forced exit.

The PowerShell tool-schema fixture is generated by replaying the pinned TypeScript source into a temporary fixture directory. Its canonical ordering and current descriptions, with the product environment prefix renamed, are the expected Rust output. A source fixture that fails against its own source is evidence to investigate, not authority for changing otherwise matching production behavior.

`waitForTurnEnd` accepts an optional `minimumTurn` in authored snapshot scripts. The numbered wait requires the latest durable turn to be closed at or beyond that number; it also accepts a turn that completed before polling began. `waitForTurnStart` retains its open-turn semantics for cancellation scenarios. The durable-catalog and policy-inheritance scenarios hold child execution behind the parent's first closed turn, then wait for the settlement turn to finish. Their authored transcripts therefore retain the same `next-turn` delivery on both fast and slow runners.

## Alternatives considered

**Exclude failing Windows suites.** This would hide supported contracts together with fixture mistakes. Native path fixtures and source comparisons distinguish those failures without shrinking the platform inventory.

**Change production ordering to fit an old snapshot.** The pinned source runtime orders these tools lexicographically. Source-generated expectations retain that behavior and keep the Rust comparison meaningful.

**Wait longer for a transient open turn.** A turn that has already closed cannot become open again. A numbered durable closing boundary tests completion without depending on polling speed.

**Discover coverage assets from the test executable.** Instrumentation changes the executable directory. Explicit paths from the owning build preserve relocated-package tests while giving coverage its required runtime.

## Consequences

The tests distinguish fixture portability, runtime behavior, installed assets, and platform execution. Cross-compilation can check Windows APIs and types, but the Windows runner still owns proof of native filesystem behavior. Focused source comparisons and snapshot runs remain separate evidence from the full workspace, coverage, real-provider, and release parity gates; none substitutes for a missing verdict.
